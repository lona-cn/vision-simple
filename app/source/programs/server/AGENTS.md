# Server contributor guide

This module builds the `server` target (`vision_simple-server`) with libhv. It hosts inference, protocol adapters, tracking sessions and subtitle jobs. Change the transport adapter and the shared service separately: do not put model loading or cache ownership in a route handler.

## Where to work

| Concern | Source |
| --- | --- |
| Listener, route mounting, legacy `/v0` handlers and `/v1/infer` streaming | `private/HTTPServer.cpp`, `private/HTTPServer.h` |
| Shared management bearer/header guard and MCP-compatible authority trust | `private/HTTPServer.cpp`, shared private `HTTPAuthority` helper |
| Task names, model factories and task-specific result packing | `private/TaskRegistry.cpp`, `private/TaskRegistry.h` |
| Decode, inference pipeline, model leases, cache and statistics | `private/InferenceService.cpp`, `private/InferenceService.h` |
| Shared response serialization, error mapping and model pagination | `private/InferenceProtocol.h` |
| OpenAI-style models/chat, MCP SSE/tools, tracking, subtitle jobs | `private/OpenAIAdapter.cpp`, `private/MCPAdapter.cpp`, `private/TrackingAdapter.cpp`, `private/SubtitleAdapter.cpp` |
| Process startup and logging | `private/main.cpp`, `private/Logger.cpp` |

## Routes and wire contracts

- Native v0/v1, OpenAI top-level chat fields and MCP inference arguments share private `InferenceRequestOptions.h` / `ParseInferenceOptions(json, InferenceKind)`. Optional numeric `confidence`/`nms_iou` are finite `[0,1]`, only for yolo/seg/pose/obb; reject bool/null/string/array/object and check original JSON double before float narrowing. Omitted confidence is 0.125; raw NMS defaults are detection 0.3, tasks 0.45. Valid end-to-end IoU is inactive: never add a second NMS. Raw detection uses strict score > confidence; end-to-end detection/tasks use >=. Masks/keypoints are unaffected. OCR rejects explicit detector controls and retains 0.125 per-token recognition suppression, not pixel/whole-line filtering.
- Validate controls before model lookup/decode, including empty arrays, without changing transport admission or cancellation/deadline/closed precedence. Semantic failures are native/OpenAI HTTP400 invalid_request (nonstreamed even with stream:true), MCP isError:true tool results using negotiated text/structured content; malformed JSON keeps its existing protocol syntax error. Advertise controls only for the four YOLO MCP tools. Errors use static reasons without echoing supplied values. Service Run/RunFrames and RunRegisteredTask take per-request YOLOInferenceOptions by value plus ServiceControl; do not mutate model/context/filter/cache keys, scheduling PipelineOptions, leases or image-budget/upload routing. Tracker Step remains independent caller input; low-confidence detector→tracker chaining is client policy.

- `POST /v0/infer/yolo` and `/v0/infer/ocr` accept JSON `{"model":"name","images":["<raw base64>",...],"timeout_ms":60000}`; `timeout_ms` is optional, 1–300000. `images` may be empty but cannot exceed `infer_max_batch_images`. YOLO responds with `class_names` and per-image `results` of `{class_id,confidence,bbox}`; OCR responds with per-image `results` of `{line,confidence,bbox}`. Boxes are `[x,y,width,height]`.
- `POST /v1/infer/{yolo|ocr|seg|pose|obb}` uses the same inference JSON and typed result shapes; these handlers enforce JSON content type and a 64 MiB body limit while streaming the upload. Segmentation includes `mask_png_base64`, pose includes `keypoints`, and OBB includes `corners` and `angle`. Task IDs come from `RegisteredTasks()`; update that registry rather than hard-coding a new `/v1` route.
- `GET /v0/infer/models` returns only the legacy `{"yolo":[...],"ocr":[...]}` view of configured models. `POST /v0/infer/unload` accepts `{"kind":"yolo","model":"name"}` (any registered task ID is valid) and returns `{kind,model,unloaded:true}`; a missing loaded entry is 404, an active one 409. `GET /v0/infer/stats?limit=100&offset=0` paginates loaded entries, not the configured catalog, returning `models`, `idle_timeout_ms`, `total`, `limit`, `offset`; limit is 1–200.
- `GET /v1/models` lists all configured tasks with IDs `task:name` and supports `limit` (1–200) plus opaque `after` cursor. `POST /v1/chat/completions` requires such a prefixed model ID and user `image_url` parts containing inline base64 image data URLs; text alone does not generate language. Its assistant `content` is serialized inference-result JSON, either in one completion or SSE chunks with `stream:true`. See `OpenAIAdapter.cpp` for accepted fields.
- MCP is `GET /mcp/sse` plus `POST /mcp/messages`; tools are `list_models` and `infer_<task ID>`, with raw model names and raw base64 image strings for inference. Tracking lives under `/v1/tracking/sessions` (create/list/get, frame step, reset, delete); subtitles under `/v1/subtitle/jobs` (create/list/get, video upload, cancel, delete, SRT/VTT download). Consult their adapters before changing payloads or session lifecycle.
- Legacy inference errors use `{"error":{"code":"...","message":"...","image_index":null}}` (index set for image-specific failures); HTTP status is set before `send()`. Error mappings are centralized in `InferenceProtocol.h`; adapter errors have their own contracts. Inference responses use `struct_json`, while handlers/adapters use `nlohmann::json` for parsing and other envelopes.

## Configuration and lifecycle

- Launch with config/server.yaml, config/models.yaml and logger configuration. Shutdown marks not-ready, BeginStop rejects/cancels dispatch work, stops subtitle/tracking/MCP, joins dispatch workers and drains IO completions while loops are alive, then stops libhv. No worker may access writer/context; Reply and final writer/context release execute on the owning IO loop.
- Native base configuration binds 127.0.0.1; Docker overrides only staged host to 0.0.0.0 after target config copy, leaving administration disabled. Do not embed or generate credentials in configuration/images.
- Only GET /v0/infer/stats and POST /v0/infer/unload are shared-cache administration. String http_management_token_env omitted/empty disables them with 403 management_disabled. An explicit conventional env name (max128) loads a visible ASCII, no-whitespace/control token (max4096) once; invalid name/missing/empty/unsafe value fails startup. External secret provisioning is required; no default env name, fallback or loopback exemption.
- Management guard runs at headers before body/100 Continue/admission/parsing/model/cache. First verify bearer (401 management_unauthorized and WWW-Authenticate: Bearer realm="vision-simple-management"), then trusted backend Host/Origin (403 management_forbidden). Case-insensitive names/scheme, case-sensitive token; constant-content-work comparison without per-auth copy/allocation. Reuse private HTTPAuthority with unchanged MCP trust: backend port, loopback or explicit nonwildcard bind; absent Origin allowed, present empty/null/malformed denied. Ignore Forwarded/X-* and query/cookie credentials.
- Stats rejects bodies; unload requires exact application/json and at most64KiB, valid Expect100-continue only after auth. Management OPTIONS403 and no permissive CORS; ordinary inference CORS/other permissions unchanged. Auth errors use native error envelope/image_index null and never log/echo secrets. Authorized requests preserve pagination400, unload404/409/200 and bounded control503 Retry-After:1. Control lane membership is not an admin permission.
- Configuration rollback removing/emptying the option disables management on the new binary; unsetting a configured secret fails startup. Old binaries ignore the option and restore unauthenticated administration: retain exact-path proxy denies/private isolation before binary rollback and verify external refusal. Tests must explicitly configure a fixture token and use admin_request only for stats/unload, not blanket inference Authorization.
- String options add http_data_workers=4, http_data_queue_capacity=4, http_control_workers=1, http_control_queue_capacity=4 (workers1–32, queues1–128). Validate at construction. Transport data/control residents, including work awaiting IO completion, stay within workers+queue independently of the service ImageCredit. Full/stopping admission returns the adapter overload envelope and Retry-After:1 before business-body parsing. Accepted inference preserves service precedence; queued work owns its body, occupies no decoded bytes/credit, and queue wait counts toward its deadline from complete-body Submit.
- GET /livez is 200 {status:alive}; GET /readyz is accepting/not-stopping 200 {status:ready}, draining 503 {status:not_ready}. Health bypasses dispatch/cache/inference locks and model loading; queue saturation is not not-ready, and health promises no model validity/warmup. Blocking native/OpenAI/tracking data runs on data lane; models/stats/unload/discovery and tracking/subtitle management/disk work use bounded control lane. Subtitle OCR keeps its existing worker.
- Subtitle video upload uses data lane, including streaming disk writes/network waits; metadata management stays on control lane. Never let a paused upload monopolize the sole default control worker.
- Subtitle FIFO follows successful FinishUpload→queued transitions under the service mutex; lexical ID List pagination is independent. Keep the bounded row scan and enqueue ordinal, not a second owning queue. Defaults remain 8 rows including terminal jobs, 60 seconds after last accepted create/BeginUpload/nonempty Append activity, 300 seconds after actual terminal acknowledgement; queued/running/cancelling have no expiry. Empty Append, reads/downloads and terminal Cancel do not touch retention.
- Subtitle expires_at is an optional UTC millisecond timepoint serialized as YYYY-MM-DDTHH:MM:SS.mmmZ/null, always present in job JSON. Capture wall+steady time at applicable touch transitions, not reads; steady alone enforces expiry, wall jumps can change the metadata estimate. Use the private typed SubtitleServiceClock source (noexcept steady_now/utc_now function pointers plus context, default real clocks); context must outlive the service. It is not SubtitleOptions, HTTP or YAML configuration.
- Independent subtitle housekeeping sweeps every real second; Add/Get/List/BeginUpload/Download also sweep. Do not add sweeps to Append/Finish/Cancel/Delete: preserve overdue-unswept winner races. Expiry is eligibility only; failed input unlink retains the row/capacity past expires_at. Download accepted under lock owns shared result storage and may finish after concurrent row deletion.
- Normal sequential keepalive must work. Concurrent same-connection HTTP pipelining while a dispatch handler still owns its writer/context is disabled by safe connection close, not by reusing the active context. Exercise partial-header/body pause, disconnect and shutdown as well as the second pipelined request.
- Existing server.yaml string options remain static_path, infer_framework, infer_ep, infer_device, infer_idle_timeout_ms, infer_sweep_interval_ms, infer_pipeline_capacity, infer_pipeline_max_batches, infer_max_batch_images, infer_timeout_ms and ocr_rec_batch_size. Validate at construction, not per request.
- Decoded-input options are positive integer strings: `infer_max_image_pixels` (16777216), `infer_max_batch_decoded_bytes` (67108864), `infer_max_inflight_decoded_bytes` (268435456). Shared v0/v1/OpenAI/MCP inference uses these limits; independent tracking does not. Preserve model/configuration precedence, then stop/deadline/close, request credit (`pipeline.max_batches`, not resident capacity), ordered strict-base64/header preflight, full-batch global reservation, decode and pipeline. Headers support PNG/JPEG/BMP/P1–P7/PF/Pf/HDR/SunRAS (WebP in enabled builds); default color decoding honors EXIF and verifies pixel count/type. `kImageLimit` maps to 400 `image_limit_exceeded` with the first single-image/cumulative-batch failure index; credit/global exhaustion maps to 503 before any decode. The BGR3 estimate is not RSS or codec scratch memory.
- Header coverage is not payload/type acceptance: actual decode must still return `CV_8UC3`. OpenCV 4.10 grayscale PFM (`Pf`) produces `CV_8UC1` even with color mode and remains rejected as `invalid_image`; do not add normalization or claim it can infer merely because its header is parsed.
- Service image_budget counters belong only to shared inference. Keep ImageCredit and decoded quota until actual native stages drain and owned input Mats die. Native HTTP and MCP disconnect/shutdown request cooperative cancellation but never hard-preempt ORT or refund early. Empty valid-model batches bypass image admission, not HTTP transport admission.
- Service/native v0/v1 valid-model empty batches preserve empty-result/control semantics and bypass image credit/quota, including saturation. Transport admission still applies. MCP tool schema retains images minItems=1 and invalid_request for empty arrays; OpenAI chat requires actual images. Never change those adapter contracts to test the native exemption.
- `models.yaml` uses `models: [{task,name,version,files}]`; `yolo` and `ocr` legacy sections are normalized by `Config` for compatibility. `(task,name)` is unique; `Config::Instance()` loads and retains the catalog on first use. Discovery does not load model weights. `InferenceService` lazily loads models by `(task,name)` and holds a mutex-protected cache; a response's lease protects active entries through serialization and records requests, failures and duration. Idle entries are swept after `infer_idle_timeout_ms` (zero disables sweeping); unload refuses active entries. Never mutate a loaded entry outside the service.

## Verify changes

- Build `server` with `xmake build server`; the executable is `vision_simple-server` (use your configured xmake target path rather than assuming a release directory). Run `xmake build test_subtitle_timeline` and `xmake run test_subtitle_timeline` for timeline changes. Run `xmake build test_subtitle_service` then `xmake run test_subtitle_service --project-root <absolute-repository-root>` for controlled-clock FIFO/expiry lifecycle regression with real OCR fixtures.
- Run python scripts/test_http_dispatch.py --server <executable> --project-root . for staged real CPU health/queue/control/MCP overlap, slow upload/response/disconnect, deadline/exception recovery and active+queued shutdown; raw RTT samples and P50/P95/P99 are emitted, with only the Docker 2s consumer deadline asserted.
- With a built executable and required real model/image fixtures, run `python scripts/test_http_regression.py --server <executable> --project-root .` from the repository root. Use the same arguments for `scripts/test_model_registry.py`, `scripts/test_protocol_regression.py`, `scripts/test_yolo_tasks_http.py`, `scripts/test_tracking_regression.py`, and `scripts/test_subtitle_regression.py` as applicable. The subtitle driver also requires FFmpeg and a font. These HTTP scripts launch isolated temporary server configurations/ports; missing fixtures fail rather than skip. `test_yolo` and `test_ocr` are interactive demos, not headless regression targets.
- Run `python scripts/test_image_budget.py --server <executable> --project-root .` for real cross-protocol predecode boundaries, global concurrency/recovery, priority and physical release on errors/cancellation/timeout/disconnect/shutdown. It uses real CPU model fixtures and public statistics, not mocks.
